# NPC intelligence contract

Additive local integration. Existing PvP APIs and Hunter production behavior stay compatible.

`npc_store.py`: `init_db()`, `ingest_snapshot(source, source_end, observed_at, rows, quality='verified', metadata=None)`; dedupe batches on (source, source_end), conflict rejects changed counts. Rows objects: system_id, npc_kills, ship_kills, pod_kills. Only source-reported systems are stored; absence is missing, never zero. Source_end and observed_at timezone-aware UTC; source_end <= observed_at. Atomic batches. `observations(days=90, quality='verified', limit=200000)` returns flat dicts source, source_end, observed_at, quality and counts; oldest first; raises on cap; `status()` summary including quality/count, coverage and audit. Native source='esi'; legacy='hunter_legacy' quality='legacy'; native ESI snapshots imported from Hunter source='esi' quality='verified' preserve original receipt time. Demo separate source='demo' quality='synthetic', never train live with demo. Database uses existing store.connect() but separate npc tables.

`npc_predictor.py`: `train(now=None)` -> status, metrics, message; saves JSON coefficients/state via store.set_state('npc_model', ...); `forecast(now=None)` -> items, model, limitations. Only verified snapshot data for live, synthetic for explicit demo mode. Never use legacy history or generated ship guesses as labels. Target: next source-reported hourly NPC count, for systems with paired observations; do not claim every absent source row is zero. Source report epochs are hourly; reject pairs outside 45..75 minutes. Historical simulation features use rows received by origin, including only known counts. Labels after origin need matured receipt; source target interval begins after latest known source period end. Conservative origin=feature receipt, target report end=source_end+1hour; forecast target may already have begun because reports delayed: state this. Chronological holdout with shared split, purge target overlap, training-only system selection, compare persistence and seasonal baseline if enough data, promote only >=2% MAE improvement on strongest baseline. Freshness check stale>2hours, expiry7days, minimum >=21days verified history, enough train/test. Refuse cap. JSON numeric finite. No forced model use; baseline remains active. Show missingness and freshness.

`npc_import.py`: explicit JSON/JSONL offline importer and audit for Hunter export. Native export envelope version1 source_end/observed_at/rows with quality verified source esi. Legacy row list from npc_activity_history stored quality legacy with source_end=observed_at (explicitly uncertain), description-only. Audit before apply; --apply imports into own SQLite only, never writes Hunter MySQL.

`npc_collector.py`: explicit enabled, contact UA, same ESI endpoint, accept 200 with Last-Modified and preserve receipt, conditional ETag only after committed batch, 304 no new sample. Honor Expires/RetryAfter; bounded timeouts/backoff; state errors/success; disabled by default. No overwriting legacy Hunter pipeline. Scope env NPC_SYSTEM_IDS optional, rows absent stay unknown. 90day training window, no automated deletion of historical data.

Root owns store, collector, importer, API/UI/docs. Forecast agent owns npc_predictor.py and tests/test_npc_predictor.py exclusively.
